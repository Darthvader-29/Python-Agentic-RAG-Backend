# Frontend Integration and API Strategy

## 1. Dynamic API Key Provisioning (BYOK - Bring Your Own Key)
Because this backend is designed for a highly configurable project rather than a strict production SaaS, hardcoding the LLM API keys in a server-side `.env` file limits flexibility.

### 1.1 Implementation Strategy
*   **Header-Based Injection:** The frontend must provide the LLM API key with every request using a custom HTTP header, such as `X-LLM-API-Key`.
*   **Dynamic Client Instantiation:**
    *   The FastAPI dependency injection system will extract this header.
    *   The `router.py`, `generation.py`, and any sub-agents will no longer rely on global `genai.configure()` calls.
    *   Instead, clients will be instantiated *per-request* using the provided key. This ensures isolation between requests and allows different users (or tabs) to use different LLM providers or keys simultaneously.

## 2. Rich Frontend Output Formatting
Currently, the LLM generates plain, unstructured text. To support a modern, interactive frontend capable of displaying text, images, and interactive applications, the backend must adapt its output format.

### 2.1 Robust Markdown & HTML Generation
The **Context Synthesis Agent** will be strictly prompted to generate highly structured output:
*   **Markdown as the Baseline:** The LLM will use Markdown for all standard text formatting (bolding, lists, headers).
*   **Image Handling:** When the LLM finds image URLs in the web search results or vector metadata, it must render them using Markdown syntax: `![Alt Text](https://image.url)`.
*   **HTML/JSON for Interactive Components:** If the user requests a chart, a form, or an interactive widget, the Synthesis Agent can output structured JSON blocks or specific HTML/React-component schemas (e.g., `<InteractiveChart data={...} />`) that the frontend is pre-configured to parse and render natively.

### 2.2 Streaming Responses
To improve perceived latency—especially critical in a multi-agent architecture where sub-agents may take several seconds to gather data—the backend must implement **Server-Sent Events (SSE)** or **WebSockets**.
*   The API will stream tokens as they are generated by the Context Synthesis Agent.
*   The API can also stream intermediate "Status" events (e.g., "Supervisor thinking...", "Searching the web...", "Querying Pinecone...") so the frontend can display a progress indicator to the user.
